2.1

这一部分做什么

先摆清它能干什么、不能干什么，省得你花两天装完发现用不上。

视频生成和第一部分正好相反：画面不是画出来的，是模型"想"出来的。你给一段文字描述和几张参考图，它给你一段几秒钟的视频，连声音一起生成。

它擅长的人物表演与口型、真实光影、场景氛围、物体质感。凡是"像实拍"的东西，它都能给你。

它做不了的画面里出现准确的文字（中文必错）、精确的 UI 界面、地图、分屏。这些必须交给第一部分或后期软件。

还有一个必须接受的现实：它有随机性。同一句话跑十次，得到十段不完全一样的视频。所以工作方式是"抽 2–3 条挑一条"，而不是"一定要出某个精确画面"。

本地跑还是用云端

AI 视频有两条路：装在自己电脑上（ComfyUI），或者用别人的服务器（LibTV 这类云端平台，打开网页就能用、按积分付费）。

对比项本地 · ComfyUI云端 · LibTV 这类
要显卡吗要，8G 显存起不要，浏览器就用
花钱方式电费 + 显卡（一次性）按积分计费，用多少付多少
出片速度一条 10–40 分钟几分钟
模型新旧要自己下、自己配永远是最新的
适合要出几十条、要反复调试创意、出单条、没显卡

结论：两者不是二选一。本地跑量和控细节，云端追新模型和快速验证。没显卡的人先把云端用起来，等真需要批量做片了再考虑本地。

2.2

先看你的显卡

这一节可能直接决定你要不要继续往下读。

视频生成要靠显卡里的显存（VRAM）来跑模型。显存不够，程序会直接报错退出或慢到没法用。这是硬门槛，绕不过去。

项目最低要求说明
系统Windows 10 / 11（推荐）或 macOSmacOS 能装，但视频生成又慢又容易缺零件，建议只用来出图
显卡NVIDIA 独显，显存 8G 起12–16G 舒服，24G 才谈得上顺畅
内存16G 起，32G 更稳有个文本编码器文件就 15G 以上
硬盘留 100G 以上模型一个几十 G，放独立硬盘更省心
显存 8G 以下、或者只有核显（Intel 集显）的：先别上本地。直接用 2.1 里说的云端平台。硬上本地的结果通常是下载了两天模型、跑三分钟出一堆报错，然后放弃——这个坑很多人都踩过。

怎么查自己的显卡

按 Ctrl + Shift + Esc 打开任务管理器 → 点「性能」→ 左侧点「GPU」→ 右上角看型号，下面看「专用 GPU 内存」。

或者更省事：直接把这句话丢给装好的 DSH——

我的显卡是 <型号>，显存 <数字>G。够跑 ComfyUI 做视频生成吗？给我一个直接的结论。
✅ 验收：你能说出自己电脑的显卡型号和显存大小；并且能明确判断"我该上本地还是先用云端"。
2.3

装好 ComfyUI

ComfyUI 是一个"节点式"的画面生成界面：把一个个方块连起来，就成了一条生成流水线。

先理解一个关键点

ComfyUI 本身不含任何模型。你装的是一个"空画布"和"连线工具"，真正的画图能力来自另外下载的模型文件（几十 G）。所以装完软件只是第一步，模型要单独下、单独放对目录——这是新手第一大坑。

三种装法

装法适合谁说明
A 桌面版（推荐）新手去 comfy.org/download 下安装包，双击装完。它自己管 Python 环境，不用碰命令行。
B 便携版想"整个搬走"的人Windows 专用，解压即用，自带 Python。里面有 run_nvidia_gpu.bat，双击启动。
C 源码要改代码的人不展开，看官方文档

便携版的目录长什么样

不管装哪种，认识这个结构就不容易迷路：

ComfyUI_windows_portable
├── ComfyUI            ← 程序主体，模型和扩展都在这下面
├── python_embeded     ← 自带的 Python，不要动
├── update             ← 升级脚本
├── run_nvidia_gpu.bat ← 双击启动（NVIDIA 显卡）
└── run_cpu.bat        ← 双击启动（仅 CPU，极慢，最后手段）

启动成功的标志

浏览器访问 http://127.0.0.1:8188，能看到一张灰色画布和一堆方块节点，就成功了。

第一次启动会刷出一大堆警告，正常，不影响使用。真报错了就把红字整段贴给 DSH 判断。

✅ 验收：浏览器能打开 127.0.0.1:8188 并看到节点画布。
2.4

下载模型与放置

这一节只做一件事：把模型下对、放对。放对了，后面才谈得上出图。

模型放在哪（最容易错的一张表）

路径都是相对 ComfyUI 根目录。放错目录 = 界面里找不到 = 你以为没装上。

类型目录用来做什么
大模型 / 检查点models/checkpoints/出图的主模型
视频扩散模型models/diffusion_models/视频生成的主模型
文本编码器models/text_encoders/把提示词翻译成模型能懂的东西
VAEmodels/vae/决定画面色彩与解码质量
LoRAmodels/loras/风格微调或加速
自定义节点custom_nodes/装扩展功能
工作流 .json不用放目录直接拖进界面

要下哪些文件（照这份清单）

下表是实际跑通过的文件清单，直接来自一台已经出片的机器。按"放到"那一列逐个放进去就行。

文件名大小放到用途
minimax_h3_hybrid_fl2va_ref2va_b25-49-int8.safetensors19.5 GBdiffusion_models/H3 主权重，混合版：首尾帧 + 参考图两用
minimax_h3_fl2va_pruned_int8_convrot.safetensors19.5 GBdiffusion_models/H3 主权重，单模式版（没有 hybrid 时才需要）
qwen3vl_32b_minimax_h3_nvfp4_awq.safetensors14.6 GBtext_encoders/文本编码器，单个最大的一件
minimax_h3_video_vae_int8_convrot.safetensors2.6 GBvae/视频 VAE，显存紧张就用这个量化版
minimax_h3_audio_vae_fp32.safetensors0.6 GBvae/音频 VAE，视频要带声音就必须有
minimax_h3_fl2v_turbo_8step_v1.0_comfyui_bf16.safetensors1.8 GBloras/Turbo LoRA，8 步出小样用
minimax_h3_turbo_v4_step600_ema_pruned_comfyui.safetensors0.6 GBloras/Turbo LoRA 另一版，和上面二选一

核心几件加起来约 40 GB（不含那个备用的 19.5 GB 主权重）。这就是前面 2.2 反复说"硬盘留 100G"的原因。

关于主权重的一条更新：文件名里带 hybrid 的那个，把「首尾帧（fl2va）」和「参考图（ref2va）」两种模式合进了一个文件——只下它一个就够。只有在没有 hybrid 版本时，才需要按模式分别下不同的权重。

方式一 · 直接拿打包好的（推荐新手）

作者已经把模型、LoRA 和出图素材打包传到夸克网盘，共 49 个文件 / 126.8 GB / 永久有效：

pan.quark.cn/s/b56c72da3ce4 —— 需要登录夸克网盘才能展开文件列表。里面除了上面这张表，还有出图模型（Krea2）和一批风格 LoRA。

下载完按上表放好即可。不要把网盘里的文件夹整个解压到 ComfyUI 根目录——网盘的目录结构不是 ComfyUI 的 models/ 结构，得一个目录一个目录对着放。

方式二 · 从魔搭（ModelScope）下

魔搭是国内的模型站，不需要科学上网，速度通常比 HF 直连快得多。

网页下：打开 modelscope.cn/models，搜 MiniMax-H3，进文件列表点单个文件下载。

命令行下（推荐，支持断点续传）：

pip install -U modelscope

# 下整个仓库到本地目录
modelscope download --model Comfy-Org/MiniMax-H3 --local_dir D:\h3-download

# 只下某一个文件
modelscope download --model Comfy-Org/MiniMax-H3 vae/minimax_h3_audio_vae_fp32.safetensors --local_dir D:\h3-download

方式三 · 从 HuggingFace 下（必须走镜像）

国内直连 huggingface.co 基本下不动，务必先设镜像，否则会一直超时。

pip install -U huggingface_hub

# 关键一步：指向国内镜像（只在当前窗口有效）
$env:HF_ENDPOINT = "https://hf-mirror.com"      # PowerShell
set HF_ENDPOINT=https://hf-mirror.com           # CMD

# 下整个仓库
hf download Comfy-Org/MiniMax-H3 --local-dir D:\h3-download

# 只下单个文件
hf download Comfy-Org/MiniMax-H3 vae/minimax_h3_audio_vae_fp32.safetensors --local-dir D:\h3-download

不想装工具也行：浏览器打开 hf-mirror.com，搜 Comfy-Org/MiniMax-H3，进文件列表逐个点下载。

LoRA 从哪来：H3 的加速 LoRA（Turbo 系列）在 HF / 魔搭的 H3 相关仓库里能搜到；社区风格 LoRA 有大量在 Civitai 上。Civitai 内容尺度差异很大，下载前看清用途和许可，别把来源不明的文件直接塞进 loras/。

下载完的两个提醒

① 文件名一个字都不要改。ComfyUI 靠文件名识别，改名之后工作流里的引用会全部失效，你会在节点里看到一堆红线。② 断了就续传，别从头下。上面的命令行工具都支持断点续传。

放完之后必须做的一步

刷新界面（按 F5 或点界面里的刷新按钮）。ComfyUI 不会自动发现新文件，不刷新的话下拉框里永远看不到你刚放进去的模型。

常见对不上号的情况：文件明明放好了，下拉框里还是没有——九成是放错目录（比如把视频模型放进了 checkpoints）或者没刷新。把目录结构和文件名截图丢给 DSH，让它帮你核对，比自己猜快得多。
✅ 验收：模型文件已按类型放进对应目录；刷新界面后，在对应的加载节点里能选中它们。
使用建议

模型放对，地基就打好了。但下一节才是真正决定成片质量的东西——prompt 怎么写。模型再好，prompt 写错也出不来能用的镜头。

2.5

装节点包（插件）

打开一个现成工作流，看到几个方块变成红色或提示 Node not found——十有八九是缺插件。这一节讲怎么补。

节点包是什么

ComfyUI 装好之后自带一批基础节点（加载模型、写提示词、出图、保存）。但很多工作流会用到别人写的扩展节点（custom nodes），比如特殊的采样器、图像处理、批量工具、界面增强。这些不在本体里，要单独装。

先说清楚一件事：H3 本身不需要额外节点包。它是 ComfyUI 0.30.0 以上原生支持的，打开模板库（Template Library → Video）就能看到它的模板。会缺节点的，通常是别人分享给你的工作流——那些作者装了各种辅助插件。

装法一 · 在 ComfyUI 的插件管理器里装（推荐）

ComfyUI 有个官方的插件管理器（ComfyUI Manager），装插件不用碰命令行。步骤：

①

找到 Manager 按钮 在界面右上角或侧边菜单里，通常写着 Manager 或「管理器」。新版桌面版一般自带。

②

点「安装缺失节点」 Manager 里有 Install Missing Custom Nodes 这一项。它会把当前打开的工作流缺了哪些插件直接列出来——这是最省事的入口，不用你自己一个个查名字。

③

逐个点 Install 列表里每一项右边有安装按钮，点一下它自己下载。装完必须重启 ComfyUI（关掉那个黑窗口，重新双击启动），刷新页面没用。

想主动搜某个插件，就在 Install Custom Nodes 里输入关键字搜索，比如 impact、was、manager。

如果界面里根本没有 Manager

便携版可能没自带，手动装一次就好——它本身也是一个节点包，装进 custom_nodes 目录：

cd <你的ComfyUI目录>\custom_nodes
git clone https://github.com/ltdrdata/ComfyUI-Manager

国内直连 GitHub 常常失败（前面第一部分踩过这个坑），给它挂上代理：

git -c http.proxy=http://127.0.0.1:7897 clone https://github.com/ltdrdata/ComfyUI-Manager

装完重启 ComfyUI，界面上就多出 Manager 按钮了。

装法二 · 管理器里搜不到，就交给你的 AI

有些插件在 Manager 的索引里没有，或者名字对不上。这时候别自己硬猜——把节点名发给你的 DSH，让它帮你查。复制这段：

我打开一个 ComfyUI 工作流，下面这些节点提示缺失或显示红色：
<把节点名逐行贴在这里>
请帮我查每个节点分别属于哪个插件包，告诉我 ComfyUI Manager 里搜什么名字；
如果 Manager 里没有，帮我在 GitHub 找到对应的 custom_nodes 仓库，并告诉我装到哪个目录。

不知道节点叫什么也没关系——把工作流截图发给它，或者把 ComfyUI 黑窗口里的红字整段贴过去，它能从报错里读出来缺的是什么。

使用建议

插件这件事有个反直觉的点：不是装得越多越好。每装一个，启动就慢一点，插件之间还可能互相打架。原则是只装当前工作流真缺的那几个，装完验证，跑通了就别再动它。

三条纪律

①

一次只装一个，装完重启验证 一次装五个，出问题你不知道是哪个引起的。

②

记下你装了什么 你把工作流发给别人时，对方也得装同样的插件才能打开。在项目里留一个 插件清单.txt 记着。

③

来源不明的不要装 custom_nodes 里的插件是能执行代码的。只从 Manager 索引或官方仓库装，别从网盘随手拿一个压缩包塞进去。

✅ 验收：你能在 Manager 里看到「安装缺失节点」这个入口；打开一个工作流时，红色节点能通过它补齐，补齐后重启不再报错。
2.6

用官方提示词规范写 prompt

H3 的提示词不是"随便描述一段画面"，它有官方规定的固定结构。这一节教你把它拿到手——而且不用你去翻 GitHub。

为什么这一节值得单独讲

同一个模型，按官方结构写的 prompt 和随口写的，出片质量差得很远。因为 H3 是"多模态参考生成"，它需要读懂很多件事：哪张图是人物、哪张是场景、哪些特征必须保留、哪些可以变、谁在说话、环境音是什么。

这套写法官方已经整理成了规范，还做成了一个可以直接装进 AI 的技能（skill）——装上去之后，你写 prompt 时它会自动按规范来，不用你背。

它在哪里

在 MiniMax 官方的 GitHub 仓库 MiniMax-AI/MiniMax-H3 里，技能名叫 h3-prompt-writing。

方法一 · 让你的 AI 自己去装（推荐）

这是这一节真正想教你的做法：你不用自己去翻网站、找文件，直接让它去找、去装、去验证。把下面这段复制给你的 DSH：

去 GitHub 找 MiniMax H3 官方的提示词编写技能（仓库 MiniMax-AI/MiniMax-H3，技能名 h3-prompt-writing），
把它装到当前工作区的技能目录里，装完把它的要点讲给我听。

它会自己完成：搜索仓库 → 下载 → 放进 .agents/skills/ → 读一遍内容再向你汇报。下不来或者装错了，就把报错原样发给它——就是 1.5 节讲的那套办法。

方法二 · 一条命令装

如果机器上装了 skills 命令行工具（不少 AI 编程环境自带）：

npx skills add https://github.com/MiniMax-AI/MiniMax-H3 --skill h3-prompt-writing

方法三 · 手动下载

打开 github.com/MiniMax-AI/MiniMax-H3，进 skills/h3-prompt-writing/ 目录，把里面的 SKILL.md 和 references/ 一起下载，放进你工作区的 .agents/skills/h3-prompt-writing/。

只复制 SKILL.md 是不够的。它里面会引用 references/ 下的示例文件，少了那些，AI 读到一半就断了。整个目录一起搬。

装完怎么确认它真的生效了

问它一句：

你现在有哪些技能？h3-prompt-writing 在里面吗？在的话，把它的工作流简述给我。

如果它能说出六段结构、能说出"台词必须包在 <d> 标签里"这类细节，就说明装好并且读进去了。

它到底规定了什么（六段速览）

你不需要背，知道"有这六块、顺序不能变"就够了，写的时候它自己会套：

段写什么
subject_definitions每个可复用的主体一条，指明它来自第几张参考图
summary一句话总述这一镜：时长、景别、地点、谁在做什么
retention_analysis逐项说明参考图的哪些特征要保留、哪些可以改
detailed_description逐镜的画面描述，350–500 英文词，按播放顺序写
overall_soundscape环境音与物理声，并声明"没有第二个说话的人"
non_diegetic_music有配乐就写配器与节奏，没有就写 N/A

三条最容易踩的硬规则

①

台词只能出现在 <d>[Mandarin] 台词</d> 里 全篇别处一个字都不要提。不包标签，模型会把它当成"要显示在画面上的文字"，直接给你糊一屏乱码。

②

说话人用 (S1) (S2) 标记 跨镜复用同一个编号。而且一段里只能有一个人说话——两个人交替，口型必然串。

③

说完要写一个收口动作 比如"她闭上嘴，目光回到老人身上"。不写，模型会让她一直动嘴。

还有一个和出图模型完全相反的点：H3 没有 negative 通道。写 no text、no subtitle 这类否定词，等于把那个概念喂给编码器，反而更容易出现。不提，才是真的不生成。这条在 2.4 提过一次，写 prompt 时最容易忘。
使用建议

这一节真正的收获不是那六段结构，而是一个做事方式：官方有什么规范、社区有什么新玩法，都不用你自己去翻——让它去找、去装、去读，你负责验收。这个习惯养成了，你就不用等别人出教程了。

✅ 验收：你能在自己的 AI 里问出 h3-prompt-writing 的六段结构；让它写 H3 prompt 时，台词确实包在 <d> 里。
