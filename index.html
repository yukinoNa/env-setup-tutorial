先读这一段

AI 做视频有两条完全不同的路。分清它们，你就不会走错门。

第一部分 · 平面动画 用代码告诉电脑"第几秒出现什么、怎么动"，电脑按帧画出来。字幕、片头、图表、地图都属于这类。不需要显卡。

第二部分 · 视频生成 用提示词和参考图让模型直接"画"出画面。人物、场景、光影属于这类。需要一张 NVIDIA 显卡。

打个比方：第一部分像你亲手做一份会动的 PPT，每个字、每个位置都由你说了算；第二部分像请一位画师，你描述，他画给你看，但他每次画得都不完全一样。

对比项第一部分 · 平面动画第二部分 · 视频生成
谁在动手代码，逐帧精确绘制模型，一次生成整段画面
文字准不准绝对精确，改一个字重出即可中文必错，不能放文字
要不要显卡不需要，普通电脑就行需要，8G 显存起步
能不能改改完重出，完全可控只能重抽，结果有随机性
擅长什么字幕、片头片尾、图表、地图、信息图人物、表演、实拍质感、光影
建议的阅读顺序：不要跳。先做第一部分（不需要显卡，当天就能看到成果），再进第二部分（要下载几十 G 模型，耗时更久）。顺序反过来的人，往往卡在下载里就先放弃了。
鲸鱼娘

我是这台 DSH 的看板娘，也是这份教程的向导。有一点先说在前面：十个人里有八个是卡在"跳过验收"上——所以每节末尾看到「✅ 验收」，就停下来做一遍再往下走。真卡住了也别去百度，把报错原样丢给 DSH，让我帮你查。

Part One

平面动画制作

用 DSH + Remotion，把文字、图表、地图做成会动的画面。这一部分不需要显卡，一台普通笔记本就能做完。

1.1

这一部分做什么

先看清楚"能做出什么"，你才知道该不该学。

平面动画就是画面里没有真人和实拍，全部由图形、文字、色块组成，但它们会动。你平时看到的片头、数据可视化、地铁线路动画、字幕特效，都是这一类。

这类画面能做什么

①

片头与片尾 标题字从画面外落下来、渐显、定格，配上机构名和副标题。这是每支片子必备的。

②

字幕与信息条 说话人的名字、日期、来源标注。手写字幕一天只能做几支，用代码生成可以批量。

③

图表与数据动画 柱状图一根根长起来、折线图从左往右画出来、数字滚动到最终值。

④

地图与路径 一张示意图上，从 A 点画一条线到 B 点，中途点亮几个地标。

⑤

信息图与示意 楼内剖面、流程步骤、对比关系。凡是"要讲清一个结构"的地方都用得上。

Remotion 是什么

Remotion 是一个让"写代码"变成"做视频"的工具。你用普通网页技术描述每一帧长什么样，它按帧渲染，最后导出成 mp4。

听起来像程序员才用的东西，但它有三个对新手特别友好的特点：

文字绝对准确"榕园小区东门"就是这六个字，不会错一个偏旁，也不会糊。

想改就改文案从"8 秒"改成"7 秒"，只要改一个数字重新渲染，而不是重新抽卡抽十遍。

关键认知：你不需要自己会写代码。这一部分真正的做法是——你负责说清楚"要什么效果"，DSH 负责写代码和渲染。你只要会描述画面，会判断结果对不对，就够了。
鲸鱼娘

接着说一件很多人不好意思问的事："我不会写代码，能学吗？"能。你要练的不是打字写代码，而是把想要的效果说成一句具体的话——"白色的字从上面掉下来，停 1 秒"这种描述，比任何语法都重要。

1.2

为什么用 DSH

不是因为它唯一，而是因为在"让 AI 帮你写动画代码"这件事上，它现在的性价比最高。

先说清楚 DSH 是什么

DSH（DeepSeek Harness）是一个"智能体工作台"。它本身不含智能——它把 DeepSeek 的模型接进来，然后给模型装上手（读写你的文件、运行命令）、记忆（记住这个项目）、约束（不许乱改你其他文件）和调度（把大任务拆成小步）。

你可以把它理解成：模型是发动机，DSH 是整台车。光买一台发动机摆在院子里，哪儿也去不了。

能力从哪来：插件生态

DSH 最特别的地方是一切皆插件——模型、工具、技能、界面，全都能换、能加。你装上什么插件，它就会什么。

插件类型装上之后能做什么
技能（Skill）把某一类活的做法教给它。比如 Remotion 的 12 个技能、字幕、地图动画、视频提示词写法
工具（Tool）给它新的手脚：连数据库、调某个平台 API、操作 Office 文件、管理系统任务
界面（UI）换主题、换皮肤、加侧边栏、加小挂件——本页右下角那只鲸鱼娘也是一种插件
模型（Model）接 DeepSeek 官方，也接任何 OpenAI 兼容的服务

装插件不用改代码：界面里有插件市场，点一下装上，重启会话就能用。你也可以直接对它说"帮我写一个插件"，它会在「创造模式」里自己写、自己装、自己验证。

插件的花样很多，光看文字说不清。建议你装好 DSH 之后，去 B 站或抖音搜一下「DeepSeek Harness」或「DSH 插件」，看别人实际用起来是什么样——十分钟的视频顶你看这里十页字。看完再回来接着读。

那为什么偏偏是它做动画

让 AI 写动画代码，比聊天难得多。聊天说错一句你可以忽略，但代码错一处，整个项目就报错、白屏、渲染不出来——它不吃"差不多"。所以能稳定干这活的模型很少。

1

目前能稳定跑通这条路的模型，基本只有两个

Claude 的 Opus 5.5 和 DeepSeek 最新模型。这是实测结论，不是宣传——写 Remotion 需要长链条的代码正确性，能扛住的模型很少。

2

而 Claude 在国内用不踏实

账号封号风险高，一旦封了，你昨天跑通的流程今天就断了。做片子是长活，最怕的不是贵，是工具箱随时失效。

3

DeepSeek 便宜，而且 DSH 把配套都做好了

成本更低只是一方面。更关键的是 DSH 里内置了整套 Remotion 技能，你不用从零教它：

remotion-createremotion-markupremotion-captions remotion-mapsremotion-multimediaremotion-interactivity remotion-renderremotion-studioremotion-docs remotion-best-practicesremotion-upgraderemotion-saas
对比项DeepSeek（走 DSH）Claude（Opus 5.5）
写 Remotion 动画代码✅ 能稳定跑通✅ 能稳定跑通

成本便宜更高
现成配套✅ 内置一整套 Remotion 技能需要自己搭
结论首选账号问题解决得了才考虑
鲸鱼娘

说句实在的：模型强不强，和你能不能一直用上它是两件事。做片子是长活，中间断一次账号，前面的分镜和素材全得重来。所以别只看跑分，先看这条路你能不能一直走下去。

1.3

装好 DSH

三件东西：一个运行环境、一个账号密钥、一个安装包。

第 1 件：Node.js

一个让电脑能跑这类程序的基础软件。打开 nodejs.org，下载标着 LTS 的那个版本（长期支持版，最稳），双击一路默认装完。

装完验证：打开终端（Windows 叫"终端"或 PowerShell），输入下面两行，各按一次回车。能看到版本号就成功了。

node -v
npm -v

如果提示"不是内部或外部命令"，说明没装上或没生效——关掉终端重新打开再试，这是最常见的假失败。

第 2 件：DeepSeek API Key

一把通行证，证明调用模型的是你、费用记你账上。打开 platform.deepseek.com，注册登录，找到"创建 API Key"，创建后立刻复制存到记事本。

密钥只完整显示一次，关掉页面就再也看不到，只能删掉重建。拿到后充一点点额度（几块钱够试验），没余额时调用会报错，而报错看着像"配置错了"，容易误判。

第 3 件：安装包

装法适合谁怎么做
A 桌面端（推荐）完全新手，只想用不想折腾打开 deepseek.com/zh/harness，下载对应系统的安装包，双击装好打开。全程点鼠标。
B 命令行愿意开一次终端的人装好 Node.js 后执行 npx @deepseek-ai/dsh web，会起在 http://127.0.0.1:3080
C 源码要改代码或写插件的人从 GitHub 仓库获取。步骤多，新手不建议。

结论：用 A。装不上或想换口味，再回来看 B。

第一次打开：两件必须做的事

1

接模型找到 设置 → 模型，把 API Key 粘进去保存。保存后立刻生效，不需要重启——很多人以为要重启，白折腾半天。

2

选工作区全新界面没选工作区时输入框是灰的、点不动，不是装坏了。点「选择工作区」→ 新建一个空文件夹（比如 dsh-试验场）→ 添加 → 再选中它。添加和选中是两步，很多人漏掉第二步。

输入框亮起来之后，先发一句最简单的试试，比如"看看这个文件夹里有哪些文件，逐个告诉我用途"。它能读出来，说明整条链路通了。

顺手认识一下权限：它真的能改你的文件，所以权限分三档——read-only（只看不改，最安全）、workspace-write（能改工作区，日常用这个）、danger-full-access（全盘可动，全自动时才用）。需要更高权限时它会先问你，每次弹窗都值得看一眼它要干什么。

必存的三个地址

用途URL什么时候用
官方快速开始deepseek-harness.github.io/deepseek-harness/guide/quickstart装之前对一眼，唯一必存的书签
模型配置deepseek-harness.github.io/deepseek-harness/guide/providers要接别的模型或自有接口时
源码仓库github.com/deepseek-ai/deepseek-harness看安全说明、提问题

✅ 验收：node -v 和 npm -v 都能看到版本号；API Key 已保存；工作区已选中、输入框能打字；它能读到你文件夹里的文件。

1.4

四步做出第一段动画

这是第一部分的核心。四步走完，你就有一条能重复用的生产线。

① 确认主题   →   ② 生成文案   →   ③ 挑选风格   →   ④ 渲染成片
说做什么       人审一遍        多方案挑一个     出 mp4

这四步的顺序不能乱，而且每一步都要你看过再往下。跳过任何一步直接渲染，回来改的成本会翻好几倍。

第一步 · 确认主题

一句话说清三件事：做什么内容、多长、给谁看。下面是真实用过的一句，可以直接改：

用 Remotion 做一段 10 秒内的动画，核心内容是科普报警急救时如何正确说清位置。

它接到这句之后，会自己去查 Remotion 的写法、确认运行环境、建好项目骨架。你不用管这些。

第二步 · 生成文案

关键动作是：先让它写文案，人审过了再往下。别让它直接开始做画面。同一句话里加上要求：

先将视频的文案写好，要通顺连贯，发给我看看。

它给你的东西大概长这样（这是真实产出的结构）：

屏时间码屏幕文案画面动作
10.00–2.40s地址说不清，救护车就在附近打转地图上光点绕圈，找不到目标楼
22.40–5.40s从大到小报：小区 → 楼栋 → 单元 → 门牌号四个词依次点亮，地图逐级放大
35.40–7.80s再补个显眼地标：超市、学校、地铁口门牌旁弹出三个地标图标
47.80–10.0s别急着挂电话，派人到路口接车车灯打到路口，有人挥手

你要审三件事：① 字数够不够装进时长——中文语速约每秒 4–5.5 字，10 秒最多约 55 字；② 连读顺不顺——让它给一版"连读全文"，你自己念一遍；③ 每屏是不是一个完整意思——别把一句话劈成两屏。

不满意就直接说"第二屏太长，压到 12 字以内"，让它重排。

第三步 · 挑选风格

这一步最容易被跳过，但它决定成片好不好看。不要让它直接渲染，先要"多方案 + 每个方案一张例图"：

这个画面风格我不太喜欢，多给我几个风格，并且每个都渲染一张例图发给我看。

它会给你 2–4 个风格方案，每个方案包含下面这些，看例图挑最顺眼的一个：

它会给你的你看什么
色板（底色 / 正文色 / 强调色 / 警示色，都给色值）整体是冷还是暖、强调色跳不跳
字体（标题用哪种、正文用哪种、数字用等宽）中文有没有糊、数字好不好读
版式（安全区边距、每行最多几个字）字太小看不清、太大压画面
动效节奏（进场、锁定各用什么曲线，禁止匀速）看例图感觉是"顺滑"还是"生硬"
节拍（多少帧一拍，音效落在拍线上）有没有踩点感

选定之后说一句"就选方案 A，按这个方案重新校对一遍分镜"，它会产出一份正式分镜，逐段写清每一帧发生什么。

风格这一步的诀窍：不要说"好看一点"——它听不懂。要说具体的："我要冷色调、医疗感、字少但大、动效干脆不要花哨"。形容词越接近你想要的方向，第一版就越接近。

第四步 · 渲染成片

到这一步你只需要说"渲染出来给我看"。它会自己在工作区里建一个工程，结构大致是：

你的项目/
├── src/
│   ├── index.jsx     ← 主画面（每一屏、每一帧都在这里）
│   └── styles.jsx    ← 风格配色（第三步选的方案）
├── public/assets/    ← 字体、音效文件
└── package.json      ← 依赖清单

渲染可能要好几分钟，取决于时长和分辨率。别在这时候催它，等它报完成。

想做什么就怎么说
先看单帧对不对先渲染第 2 秒那一帧给我看（比渲染整段快得多）
改文案第二屏的字改成"从大到小报：小区、楼栋、单元、门牌号"，其他不动
调节奏第三屏停留太短，多给 0.5 秒，后面整体顺延
导出终版按 1920×1080、30fps 导出完整 mp4
一个要提醒你的现实：第一次跑，它很可能报错——缺依赖、端口被占、字体找不到。这非常正常，不是你的问题，也不是它笨。正确做法是把完整报错原样贴回去让它自己修。这一节真正的技能，是"把报错交出去"。
鲸鱼娘

做动画这件事，第一版永远不是最终版。真实情况是：5 秒的片头，通常要来回改七八次。别指望一句话出完美效果，要指望的是每一轮都能明确知道"哪里不对、下一句该改什么"——这个能力比什么都值钱。

✅ 验收：你走完了四步、拿到一段能播放的 mp4；文字和你要的一字不差；你至少成功让它改过一次（说明这个循环闭环了）。
1.5

卡住了怎么办

这一节是整份教程里最该反复回看的一节。

核心观念只有一句：装环境这件事，不需要你自己扛——DSH 本身就是最好的排查工具。

新手最常见的错误是：一看到红字就打开搜索引擎，翻十几个帖子，试七八种互相矛盾的办法，最后把环境搞得更乱。正确做法是把问题直接丢给它——它能看你的文件、能执行命令、能读日志，比任何论坛帖子都更了解你这台机器的实际情况。

五个可以复制的提问模板

检查我电脑上 Node.js 和 npm 的版本，告诉我能不能跑 DSH
我执行 XXX 时报了这个错：〈把完整报错原样粘贴在这里〉，帮我判断原因并给修复步骤
告诉我 DSH 的配置文件和日志分别存在哪个目录，各自是干什么的
列出你现在能用的工具和技能，并告诉我哪些适合用来做动画
按官方文档帮我一步步装好 ComfyUI，每一步都要告诉我该点哪里

三条提问纪律

1

报错贴原文，不要转述"它说找不到什么东西"等于没说。完整报错里有文件名、行号、错误码，那才是线索。

2

说清你想要什么结果别只说"报错了"，要说"我想让它跑起来之后能导出 mp4"。目标清楚，它才不会给一堆无关方案。

3

一次只解决一个问题三件事塞进一句，只能得到三个半吊子答案。解决一个、验证一个、再问下一个。

另外三条运维习惯

① 升级前先备份。配置默认在用户目录下的 .dsh 文件夹里（隐藏文件夹）。它是纯文本，复制一份到别处即可。② 出问题先看 logs 目录，同样在 .dsh 下面。不会找就用上面第 3 个模板直接问。③ 遇到怪事先确认版本——昨天还能用的配置今天失效了，先怀疑版本，别怀疑自己。

✅ 验收：你记住了"报错原样丢给 DSH"这个做法；能给 .dsh 做一次备份；知道日志在哪。
Part Two

视频生成平台

用 ComfyUI 把 AI 画出来的画面变成视频。这一部分需要一张 NVIDIA 显卡，也要下载几十 G 模型，比第一部分重。

2.1

这一部分做什么

先摆清它能干什么、不能干什么，省得你花两天装完发现用不上。

视频生成和第一部分正好相反：画面不是画出来的，是模型"想"出来的。你给一段文字描述和几张参考图，它给你一段几秒钟的视频，连声音一起生成。

它擅长的人物表演与口型、真实光影、场景氛围、物体质感。凡是"像实拍"的东西，它都能给你。

它做不了的画面里出现准确的文字（中文必错）、精确的 UI 界面、地图、分屏。这些必须交给第一部分或后期软件。

还有一个必须接受的现实：它有随机性。同一句话跑十次，得到十段不完全一样的视频。所以工作方式是"抽 2–3 条挑一条"，而不是"一定要出某个精确画面"。

本地跑还是用云端

AI 视频有两条路：装在自己电脑上（ComfyUI），或者用别人的服务器（LibTV 这类云端平台，打开网页就能用、按积分付费）。

对比项本地 · ComfyUI云端 · LibTV 这类
要显卡吗要，8G 显存起不要，浏览器就用
花钱方式电费 + 显卡（一次性）按积分计费，用多少付多少
出片速度一条 10–40 分钟几分钟
模型新旧要自己下、自己配永远是最新的
适合要出几十条、要反复调试创意、出单条、没显卡

结论：两者不是二选一。本地跑量和控细节，云端追新模型和快速验证。没显卡的人先把云端用起来，等真需要批量做片了再考虑本地。

2.2

先看你的显卡

这一节可能直接决定你要不要继续往下读。

视频生成要靠显卡里的显存（VRAM）来跑模型。显存不够，程序会直接报错退出或慢到没法用。这是硬门槛，绕不过去。

项目最低要求说明
系统Windows 10 / 11（推荐）或 macOSmacOS 能装，但视频生成又慢又容易缺零件，建议只用来出图
显卡NVIDIA 独显，显存 8G 起12–16G 舒服，24G 才谈得上顺畅
内存16G 起，32G 更稳有个文本编码器文件就 15G 以上
硬盘留 100G 以上模型一个几十 G，放独立硬盘更省心
显存 8G 以下、或者只有核显（Intel 集显）的：先别上本地。直接用 2.1 里说的云端平台。硬上本地的结果通常是下载了两天模型、跑三分钟出一堆报错，然后放弃——这个坑很多人都踩过。

怎么查自己的显卡

按 Ctrl + Shift + Esc 打开任务管理器 → 点「性能」→ 左侧点「GPU」→ 右上角看型号，下面看「专用 GPU 内存」。

或者更省事：直接把这句话丢给装好的 DSH——

我的显卡是 <型号>，显存 <数字>G。够跑 ComfyUI 做视频生成吗？给我一个直接的结论。
✅ 验收：你能说出自己电脑的显卡型号和显存大小；并且能明确判断"我该上本地还是先用云端"。
2.3

装好 ComfyUI

ComfyUI 是一个"节点式"的画面生成界面：把一个个方块连起来，就成了一条生成流水线。

先理解一个关键点

ComfyUI 本身不含任何模型。你装的是一个"空画布"和"连线工具"，真正的画图能力来自另外下载的模型文件（几十 G）。所以装完软件只是第一步，模型要单独下、单独放对目录——这是新手第一大坑。

三种装法

装法适合谁说明
A 桌面版（推荐）新手去 comfy.org/download 下安装包，双击装完。它自己管 Python 环境，不用碰命令行。
B 便携版想"整个搬走"的人Windows 专用，解压即用，自带 Python。里面有 run_nvidia_gpu.bat，双击启动。
C 源码要改代码的人不展开，看官方文档

便携版的目录长什么样

不管装哪种，认识这个结构就不容易迷路：

ComfyUI_windows_portable
├── ComfyUI            ← 程序主体，模型和扩展都在这下面
├── python_embeded     ← 自带的 Python，不要动
├── update             ← 升级脚本
├── run_nvidia_gpu.bat ← 双击启动（NVIDIA 显卡）
└── run_cpu.bat        ← 双击启动（仅 CPU，极慢，最后手段）

启动成功的标志

浏览器访问 http://127.0.0.1:8188，能看到一张灰色画布和一堆方块节点，就成功了。

第一次启动会刷出一大堆警告，正常，不影响使用。真报错了就把红字整段贴给 DSH 判断。

✅ 验收：浏览器能打开 127.0.0.1:8188 并看到节点画布。
2.4

下载模型与放置

这一节只做一件事：把模型下对、放对。放对了，后面才谈得上出图。

模型放在哪（最容易错的一张表）

路径都是相对 ComfyUI 根目录。放错目录 = 界面里找不到 = 你以为没装上。

类型目录用来做什么
大模型 / 检查点models/checkpoints/出图的主模型
视频扩散模型models/diffusion_models/视频生成的主模型
文本编码器models/text_encoders/把提示词翻译成模型能懂的东西
VAEmodels/vae/决定画面色彩与解码质量
LoRAmodels/loras/风格微调或加速
自定义节点custom_nodes/装扩展功能
工作流 .json不用放目录直接拖进界面

配套素材从哪来

本教程配套的模型和工作流文件统一放在网盘：〈网盘链接待补〉。下载后按上面的表逐个放进对应目录。

如果网盘不全，也可以自己下。模型发布在 Comfy-Org/MiniMax-H3 仓库。国内直连 HuggingFace 很慢，把地址里的 huggingface.co 换成 hf-mirror.com 再下载，通常会快很多。

要下什么大概多大心理准备
Qwen3-VL 32B 文本编码器15.7 GB单个最大的一件，下它最耗时
视频 VAE（int8 量化版）2.8 GB显存紧张就用这个
FL2V Turbo LoRA2.0 GB用来 8 步快速出小样
音频 VAE0.6 GB视频要带声音就得有

以上只是配套件，视频主权重（fl2va / ref2va）另算，合计远超 20GB。所以前面 2.2 才反复强调硬盘要留 100G。下载慢是正常的，断了就续传，别反复从头下。

放完之后必须做的一步

刷新界面（按 F5 或点界面里的刷新按钮）。ComfyUI 不会自动发现新文件，不刷新的话下拉框里永远看不到你刚放进去的模型。

常见对不上号的情况：文件明明放好了，下拉框里还是没有——九成是放错目录（比如把视频模型放进了 checkpoints）或者没刷新。把目录结构和文件名截图丢给 DSH，让它帮你核对，比自己猜快得多。
✅ 验收：模型文件已按类型放进对应目录；刷新界面后，在对应的加载节点里能选中它们。
鲸鱼娘

到这里第二部分先告一段落——模型放对，这一部分的地基就打好了。接下来怎么用它出图、出带声音的视频、怎么套用别人做好的工作流，等我把后续几节补上再来。别急着乱试，先确认目录对了。

  3. 一次只解决一个问题。
